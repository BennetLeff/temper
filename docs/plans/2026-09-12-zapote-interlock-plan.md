# Standalone safety interlock

Build the next separate unit after thermal Rev B. Atopile source, native KiCad placement/routing, Rust truth validators and current evidence are the deliverable. Do not integrate or energize the cooker. Existing gate-drive and sensor boards remain unchanged.

The unit accepts seven active-high fault inputs: primary overcurrent, overvoltage, heatsink, coil, RTD, MCU runaway, and auxiliary protection (secondary OCP / logic UVLO aggregate). Each is pulled high locally so a broken signal wire requests shutdown. An independently driven SENSOR_LIVE input is pulled low and must represent qualified sensor power/availability. Existing sensing boards do not yet provide this combined signal; implementing its producer is an explicit later integration obligation, never a claim of present fault-safe wiring.

Two SN74LVC14ADR hex Schmitt inverters normalize the seven faults, condition an active-low reset request, and invert the NAND fault aggregate. A CD74HC30PWR combines seven healthy fault states and a common-good signal. SN74LVC1G08DBVR ANDs SENSOR_LIVE and the TPS3823-33DBVR reset output into common-good. The watchdog input has a pulldown so an absent MCU cannot disable the watchdog by leaving WDI floating. TPS3823 provides startup holdoff and its own brownout response, not the different legacy UVL-02 threshold specification; that dedicated protection feeds AUX_FAULT.

SN74LVC1G74DCUR has D and PRE_N tied high, CLR_N driven by all-good, and CLK driven by the inverted reset request. Q (pin 5) is PERMIT, locally pulled down. Q-bar (pin 3) is LATCHED_FAULT telemetry. Every fault clears permission regardless of reset; removing a fault does not restart; a held reset request cannot restart after a fault clears. A new qualified falling RESET_N edge is required. Do not transfer the incorrect Q/Q-bar pin mapping from plain-text assumptions. The donor TPS3823 definition also has swapped GND/RESET pins; this standalone unit defines the datasheet-correct RESET_N1/GND2 locally and records the donor defect for later reconciliation.

PERMIT is the authoritative gate-drive interface. The downstream gate unit must require actively driven permission and use its own pulldown; the complement is not assumed driven during power loss. Static digital behavior, every fault combination, state transitions, cold startup, timeout, simultaneous fault/reset, reconnection and held reset require Rust counterexamples. Device timing, power ramps, metastability windows, external input loading, missing returns and SENSOR_LIVE production remain explicit applicability/physical qualification obligations. No broader cooker safety certification is implied.

Boundaries: J1 has GND then the seven fault inputs. J2 has +3V3, GND, WDI, RESET_N, SENSOR_LIVE, PERMIT, LATCHED_FAULT and WDT_RESET_N. Supply 3.135–3.465V; healthy remote fault outputs must hold <=0.3V and assert >=2.7V. Reset and WDI are driven logic, not unconditioned mechanical switches. Declare pull/load budgets and reset timing before acceptance.

Exit criteria: exact compiled/native pin map and connected-net clusters; source-bound device topology; Rust negative corpus and workspace checks; real saved-board stackup; native ERC/DRC/parity with zero construction violations; readable schematic/PCB renders; separate qualification findings; versioned memory use and a frozen manifest. Existing Python adapters only transport native changes, with no new placer/router algorithms. Luna implements bounded isolated tasks; coordinator verifies and commits locally. No push, purchase or fabrication.
