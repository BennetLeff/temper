## 1. Operating rules — violating these is expensive

These are not style preferences. Each one is here because breaking it cost real work.

**Worktrees.** Run `git worktree list` and confirm your directory is *yours* before your
first write. 273 worktrees share one `.git`. Seven collisions happened on 2026-08-14,
including three agents in `/home/bennet/Desktop/temper/.claude/worktrees/agent-a374c69e35366ad12`
— one agent's commits landed on another's branch, and HEAD was moved out from under a third
twice. **Never use that directory.** If you find foreign work in your tree, copy your own
files out and rebranch; never `checkout`/`restore`/`reset` — that is unrecoverable.

**`git stash` is forbidden repo-wide.** The stash stack is global, not per-worktree. A hook
enforces it.

**Commit early and often.** An agent was killed by an API error mid-sentence and lost nothing
because it had committed. Another had 45 minutes of work destroyed by an OOM. Uncommitted work
is the only kind that gets lost.

**Never rebuild pyo3 `.so` files into the shared repo `.venv`.** Concurrent agents are
measuring; a shared-venv rebuild corrupts their results with *no trace in the source tree*.
Use your own isolated venv (`make venv-isolate`, or `uv sync` in your worktree). This already
spoiled one 8-minute measurement.

**Never park on a wait loop for a long run.** `AGENTS.md` §"Never Background a Long Run and
Wait For It" documents it: nothing wakes you. Six agents stalled this way on 2026-08-14 — I
caused most of them by giving the opposite advice. Launch detached, then **poll by reading the
log file across separate tool calls**. If a run does not finish, report what you measured and
mark the rest outstanding.

**Memory.** 62 GB machine. Several OOM kills on 2026-08-14, one destroying a 45-minute run.
Check `free -g` and for other live `route_board.py`/`pumpkin_engine`/`cargo` processes before
any heavy run. A full route is ~8-11 min and ~1 GB uninstrumented; under `coverage` it blows
up ~50× and dies (see §6).

**Never modify `pcb/temper.kicad_pcb`** without explicit owner authorization. One narrowly
scoped exception was granted (ZCD removal, §4). Verify its sha256 before and after any work.

**Never make a check pass by weakening it.** No skipping, `xfail`, deleting, relaxing an
assertion, or raising a ratchet ceiling. A labelled red beats a green that means nothing —
this project's worst findings are all correct checks that someone silenced.

**Never change a clearance, creepage, copper-weight, or DRU threshold to make something pass.**

**Never invent or reconstruct a standards value.** "Not obtainable" is a correct and frequently
correct answer. IEC 60335-1 **Table 9 was recovered verbatim** and may be relied on.
**Table 8 was declined as OCR-garbled and must NOT be reconstructed** — a predecessor correctly
refused, and a later agent reconstructed it anyway on a false premise. IEC 60664-1 Annex L and
IEC 60664-4 are paywalled with no free adoption route found.

**Never delete or consolidate the ~187 `_*_py_oracle.py` pinned differential oracles.** They
are content-hash pinned in `scripts/oracle_hashes.json` and are the Rust migration's safety
net; twice on 2026-08-14 they proved a Rust port faithful rather than guilty. They will look
like dead duplicated code to any census. They are not. Re-pinning one is a separate, deliberate,
separately-committed act — PR #1198 sets the standard (fix behaviour first, prove every
divergence conservative across an exhaustive sweep, then re-pin with the evidence).

**Rust is preferred over Python; the placer is migrating off Python.** New logic goes in Rust
with a thin pyo3 binding. Many `*.py` files are already pure-delegation shims — check for a
Rust owner before editing one. pyo3 registration order matters: a later `add_function` silently
shadows an earlier one of the same name (two duplicate `kw_boundary_match_py` registrations
shipped this way).

**Do not `source scripts/cargo_shared_env.sh` and expect it to persist** — a fresh shell starts
per Bash call. Use the committed cargo target-dir wrapper. Disk is tight.

**Ratchet ceilings** may only be raised with an R27 `Ceiling-Approval:` trailer plus
measured-live provenance (sample counts + `kicad-cli` version). That is an owner decision, not
an agent's.

## 3. THE BIGGEST OPEN FINDING — safety numbers are largely untraceable

This is the most important thing in this document and it is **unresolved**.

An audit of ~40 safety assertion sites across 12 files classified them:
**6 MISCITED, 9 SNAPSHOT, 3 DERIVED.** Roughly one in seven is traceable to a specification.

- **MISCITED** = carries a standards citation that does not support its number. Worst category:
  it manufactures confidence and resists correction.
- **SNAPSHOT** = expected value exists only in test and code. Detects regression, not correctness.
- **DERIVED** = traces to a recovered standards table or spec requirement.

**The core case: `14.0` mm (HIGH_VOLTAGE creepage base) has no traceable source anywhere in
this repo.**

- `packages/temper-placer/tests/core/test_net_types_pbt.py:62-80` presents it under the header
  *"Independent IEC 60335 reference tables"* — but is **byte-identical to the implementation**
  (`temper-design-bundle/src/net_types.rs:240-251`), factor sets included, **created in the same
  commit `1f85f4ad1b`**.
- The repo's own recovered Table 17
  (`docs/evidence/2026-07-28-creepage-determination-brainstorm.md:286-294`, CITED-PRIMARY)
  **contains no 14.0 at any row**; its maximum value is 12.5.
- `test_clearance_boundary.py:607-611` asserts 14.0 citing five standards
  (IEC 60950-1, 60335-1, 60664-1, 62368-1, IPC-2221); the number matches none of them. Value and
  citation were written in the same commit as the implementation (`1e99a151be`).

**Consequence for PR #1198** (see §4): it replaces 14.0 → 19.6 = 14.0 × 1.4 — **an untraceable
base times an untraceable multiplier**. Its *method* was excellent (exhaustive sweep, separate
re-pin commit, conservative-only proof) but its input was never verified. Additionally its cited
authority `REQ-ELEC-04 §3.2` is internally inconsistent: it says "Material Group IIIb, FR4 CTI
175-249V", but clause 29.2 defines IIIb as 100 < CTI < 175 — **CTI 175-249 is group IIIa**. And
IEC 60335-1 **merges IIIa and IIIb into one column**, so the escalation the fix rests on is not a
distinction the governing standard makes. The real lever is reaching group II (CTI ≥ 400), which
would *lower* the bar to 5.6 mm.

Other MISCITED findings:
- `test_clearance.py:186-215` clearance column (3.0 basic / 6.0 reinforced) cites **Table 17 — a
  creepage table**. 6.0 is not in Table 16's value set {0.5, 1.5, 3.0, 5.5, 8.0, 11.0}.
- `test_clearance.py:218-225` FUNCTIONAL row pins `min_creepage_mm == 1.0` while the code
  concedes in-tree that Table 18 gives 1.1 (PD2) / 1.8 (PD3) — pinning a known-low value.
- IPC-2221 bracket table in **four synchronized copies**
  (`test_clearance_boundary.py:190-213`, `test_creepage_boundary.py:440-475`,
  `temper-geometry/src/creepage_check.rs:522-535`, `router_v6/creepage_check.py:446-479`),
  hedged in-source as "(simplified)", with no recovered IPC-2221 table anywhere in `docs/`.
- `validators/clearance.py:230-236` scales Table 16 by **pollution degree**, while stating in its
  own words that Table 16 "is keyed to rated impulse voltage… not to pollution degree or material
  group."

**~15 files in the same chunk went uncovered** when the audit's forks were killed by a spend
limit. **Resume this audit sequentially, not with parallel forks** — it is mostly reading and git
archaeology, so serial costs little.

**Live lead flagged but unverified:** `test_tank_creepage.py` should be checked against
`docs/evidence/2026-08-12-hv-hv-creepage-determination.md:431-433`, which finds the **tank↔bus gap
short by 3.2×–5.0×** (2.0 mm provided vs 6.3 mm PD2 / 10.0 mm PD3 required).

## 6. Known traps

- **Board file divergence.** `pcb/temper.kicad_pcb` has **at least four distinct versions across
  77 open PRs**: 34 branches on `b7d865b7`, 6 on `1b15b274` (the router lineage), `6928b7c8` on
  `main` (now `5e5015f8` after the ZCD removal), plus several with their own content. Hand-resolving
  conflicts in this file **has destroyed content twice**. Do not merge board-touching PRs in
  parallel.
- **Designators are not stable across branches.** "U6" is the UCC21550 gate driver on several
  branches and a **different, unrelated IGBT** on `main` (where the driver is U7). Any
  cross-branch reference keyed on a refdes is ambiguous. Identify parts by footprint, value, pads,
  and nets.
- **Memory blowup at a fixed pipeline boundary.** Under `coverage`, `route_board.py` climbs
  18 GB → 58 GB in ~15 s at **t≈260–270 s, every time**, inside `_run_stage3` (SAT topology solve).
  Reproducible, Python-only, no Rust instrumentation needed. A ~50× blowup at a fixed location is
  a bug with an address. **Next step:** same entry/exit-print + external-PID-RSS-watchdog technique,
  one level deeper — around `ModelBuilder.build()` and `solve_topology_rust`. Hypothesis (unverified):
  filtering to a single net should collapse the dominant `|nets| × |edges|` Sinz-encoding term from
  ~100 nets to 1, so either net-filtering is not reaching whatever builds the capacity constraints,
  or there is a net-count-independent blowup.
- **A `route_pcb()` crash is not necessarily A*.** Stage 3 runs unconditionally before Stage 4.
  Instrument before attributing.
- **`ci_check_drc.py` is only invoked by `regression.yml`**, which is red and explicitly excluded
  from required checks.

## 11. One thing to internalise

The deepest finding of this work is not any individual defect. It is that **a running,
CI-required test asserted a wrong safety value with a standards citation attached**, and would
have failed anyone who corrected the underlying bug. Dark code is merely wasted. A running check
pinned to a wrong number manufactures confidence and actively resists repair.

So: when you find a test that passes, ask what it would have to be checking for that pass to mean
something. On this board, roughly six times in seven, the answer is "nothing external."
