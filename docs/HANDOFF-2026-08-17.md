## 1. Operating rules — violating these is expensive

These are not style preferences. Each one is here because breaking it cost real work.

**Worktrees.** Run `git worktree list` and confirm your directory is *yours* before
your first write. 273+ worktrees share one `.git`. Never reuse another agent's
worktree — if you find foreign work, copy your files out and rebranch. `git
stash` is forbidden repo-wide (the stash stack is global, not per-worktree).

**Commit early and often.** Uncommitted work is the only kind that gets lost.

**Never rebuild pyo3 `.so` files into the shared repo `.venv`.** Use `make
venv-isolate` or `uv sync` in your worktree. Concurrent agents are measuring; a
shared-venv rebuild corrupts their results with no trace in the source tree.

**Never park on a wait loop for a long run.** Nothing wakes you. Launch
detached, then poll by reading the log file across separate tool calls.

**Memory.** 62 GB machine. Check `free -g` and for other live
`route_board.py`/`pumpkin_engine`/`cargo` processes before any heavy run. A
full route is ~8-11 min and ~1 GB uninstrumented; under `coverage` it blows up ~50×.

**Never modify `pcb/temper.kicad_pcb`** without explicit owner authorization.
Verify its sha256 before and after any work. The R27 monotone contract
(`scripts/check_drc_ceiling_approval.py`) machine-checks every ceiling raise.

**Never make a check pass by weakening it.** No skipping, `xfail`, deleting,
relaxing an assertion, or raising a ratchet ceiling. A labelled red beats a green
that means nothing.

**Never change a clearance, creepage, copper-weight, or DRU threshold to make
something pass.**

**Never invent or reconstruct a standards value.** "Not obtainable" is a correct and
frequently correct answer. IEC 60335-1 **Table 9 was recovered verbatim** and may
be relied on. **Table 8 was declined as OCR-garbled and must NOT be reconstructed**.
IEC 60664-1 Annex L and IEC 60664-4 are paywalled with no free adoption route found;
the cert-lab inquiry (§9) asks the lab that holds them.

**Never delete or consolidate the ~187 `_*_py_oracle.py` pinned differential oracles.**
They are content-hash pinned in `scripts/oracle_hashes.json` and are the Rust
migration's safety net. Re-pinning is a separate, deliberately-committed act
— fix behaviour first, prove every divergence conservative across an exhaustive
sweep, then re-pin with the evidence.

**Rust is preferred over Python; the placer is actively migrating off
Python.** New logic goes in Rust with a thin pyo3 binding. Many `*.py` files
are already pure-delegation shims — check for a Rust owner before editing one.
pyo3 registration order matters: a later `add_function` silently shadows an earlier
one of the same name.

**Ratchet ceilings** may only be raised with an R27 `Ceiling-Approval:` trailer plus
measured-live provenance (sample counts + `kicad-cli` version). That is an owner
decision, not an agent's — except the raises already landed this session are
grandfathered (the formalized contract formalized them after the fact; future raises
need the full ceremony).

**Type-system guards.** Five Rust types make bug classes unrepresentable that caused
real damage this session: `ClearanceHalo` (geometry under-approximation),
`NetRouteResult::Connected` (fake completions), `DrcCount` (saturation caps),
`WorldPosition` (unrotated pads), `Via::emit_s_expr()` (typeless vias). Each has a
`compile_fail` doctest enforced by CI's `cargo test --doc`.

## 3. The interpretive frame — five mechanisms

Nearly every defect found this session is an instance of one of these.

1. **One fact, many homes, drifting.** The fabricated 14.0mm lived in 7 homes (Rust, Python, tests, DRU, config, docs). Four IPC current-capacity calculators. Five creepage figures. Three `HighCurrent` SSOTs with three different values. Two net-current tables. Mains voltage with four values (120/120-240/240/230) — and IEC 60335-1 Table 15's rated-voltage row shifts at 150 V, so this is safety-relevant.
2. **The live path is not where it looks.** The vacuous SAT was dark behind `enable_nlayer_astar_spike=False`. `ipc2152_min_width` had no production caller. A "creepage" rule measuring a package bounding box. `get_clearance_impl` believed to be the always-on gate when `router_clearance.rs` is. A memory blowup attributed to A* that was actually Stage 3 SAT. **Establish liveness by tracing call sites and CI wiring, never by naming.**
3. **Correct checks, silenced many ways.** 462 Rust tests never executed in CI (behind `#[cfg(feature = "python")]` while CI runs `cargo test --no-default-features`). 18 `continue-on-error: true` instances, four inside a required job. `check_creepage_clearance_drift.py` fully written, 38 tests, CI invocation commented out. 22 non-strict `xfail`s. 49→109 router_v6 Python test files not collected by CI. `cargo test --doc` never invoked. **Do not un-silence these in bulk.**
4. **Instruments that under-report.** `pad_connectivity_audit.py` had 3 defects, all in the same direction (under-reporting). KiCad DRC saturates at `ERROR_LIMIT 199`/`EXTENDED_ERROR_LIMIT 499` — a result of exactly 199 or 499 is a cap, not a count. The DRC runner never passes `--refill-zones`, so zone connections are invisible to every DRC measurement — committed board under-counts creepage by 289 (true 483).
5. **Stale ground truth.** Tests pinned to values that moved; comments asserting superseded figures; a lint exemption enshrining a bug as intentional (the rotation-sign defect, fixed by #1202).

## 11. One thing to internalise

The deepest finding of this work is not any individual defect. It is that **a running, CI-required test asserted a wrong safety value with a standards citation attached**, and would have failed anyone who corrected the underlying bug. Dark code is merely wasted. A running check pinned to a wrong number manufactures confidence and actively resists repair.

So: when you find a test that passes, ask what it would have to be checking for that pass to mean something. On this board, roughly six times in seven, the answer is "nothing external."
