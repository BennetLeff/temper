# Rust zone generator wired into production emission (2026-08-16)

**Purpose**: wire agent 64's Rust zone-pour outline generator
(`packages/temper-geometry/src/zone_generator.rs`, prototype on
`feat/rust-zone-pour-design` per `docs/evidence/2026-08-15-rust-zone-pour-
design.md`) into the production emission path
(`router_v6/_zone_pour_stitch.py::_emit_zone_pours`), closing the three
measured defects that document classifies: hole-less outlines (167
isolated_copper islands), clearance-only carve (2.00mm vs 12.6mm creepage
violation), and 47+ island fragmentation for `power_in.ntc-no`.

**Branch**: `feat/wire-rust-zone-generator` (worktree
`/tmp/opencode/agent-wire-zones`), base `origin/main` @ `fdbe0a6ad` +
the three prototype commits cherry-picked (`fe8dd134c`, `67bb52350`,
`f1937b2c2`).

---

## 1. What changed

### 1.1 The emission seam

`_emit_zone_pours` now, per zone-eligible net/layer:

1. Builds the per-net foreign-copper obstacle list with
   `zone_pour_clearance.collect_zone_obstacle_records` -- the same
   geometry walk `pair_clearance_keepout` used (pcb pads/tracks/vias +
   this route's emitted segments/vias, same "other zones not carved
   against" decision), but one **structured record per item** whose
   separation is `max(clearance_table.required, creepage_table.required)`
   for that net-class pair.
2. Calls `temper_geometry.pour_outline_py(region, own_pads, obstacles,
   min_island_area, pads_only)` -- the Rust core (keepout-union +
   `geo::BooleanOps` carve, hole-preserving `ZoneOutline`, deterministic
   ordering).
3. Emits each resulting outline via
   `temper_geometry.emit_zone_outline_s_expr_py` -- one `(polygon
   (pts ...))` element per ring (exterior first, holes after), the format
   KiCad's own writer produces and its parser documents ("The first
   polygon is the main outline. Others are holes").

The old Python carve (`pair_clearance_keepout` + `_carve_outline`) is
kept in place (still used by its own unit tests) but is no longer on the
production path.

### 1.2 The creepage twin table

New `configs/zone_pour_creepage.generated.yaml`, generated by
`scripts/generate_kicad_dru.py` (`derive_zone_pair_creepage_matrix` /
`render_zone_pair_creepage_yaml`) by evaluating the DRU's **creepage**
constraints under KiCad's last-matching-rule-wins precedence -- the same
two-step resolution the clearance twin already performs, with 0.0 as the
"no creepage rule matches this pair" fallback (KiCad applies no creepage
check to it; the clearance twin still protects it).

Measured values from the committed table:

| pair | clearance | creepage | carve uses |
|---|---|---|---|
| HighVoltage \| Power (HV↔LV) | 2.0 | **12.6** | 12.6 |
| ACMains \| Default (mains↔LV) | 6.0 | **12.6** | 12.6 |
| HighVoltageTank \| HighVoltage (HV↔HV functional) | 2.0 | **10.0** | 10.0 |
| Power \| Power (LV↔LV) | 0.5 | 0.0 | 0.5 |
| Default \| Default | 0.2 | 0.0 | 0.2 |

Loader: `router_v6/zone_pour_creepage.py` (`ZonePourCreepageTable`,
mirroring `zone_pour_clearance.py`'s table, unknown class → Default,
unknown type → strictest across named types).

### 1.3 Island policy

`pads_only = (netclass != "GND")`: every pour except GND-class return
planes drops padless pieces. Rationale from the design doc's
`IslandPolicy` guidance: padless islands on signal/HV/mains pours are
pure isolated_copper liability; a return plane wants padless copper for
plane continuity/shielding. ACMains is deliberately NOT given the plane
treatment: an isolated padless island at mains potential is a hazard,
not shielding.

Consequence measured by agent 64 (design doc §7): `power_in.ntc-no`'s
single hull at PD3 creepage covers **0/4 pads**, so PadsOnly drops every
piece and the net emits **no zone at all** -- the honest "pour infeasible
at PD3" answer, instead of the old 47+ misleading islands. ntc-no still
gets its pad-to-pad MST connectors via `_stitch_pads_to_each_other`
(unchanged, 2026-08-14 behavior).

### 1.4 pyo3 return-format fix

The prototype's `pour_outline_py` returned a flat
`[exterior..., n_holes, hole0..., ...]` list with only the HOLE lengths
prefixed -- the Python side could not locate the exterior ring's end
(no exterior count).  As the first production consumer, this wiring
changed the return to structured `Vec<Vec<Vec<(f64, f64)>>>`
(zone → rings → points, ring 0 exterior) -- unambiguous by construction.
The pure-Rust core and its 8 unit tests are unchanged.

### 1.5 geo 0.28 -> 0.29 (BooleanOps engine)

geo 0.28's sweep-line `BooleanOps` panics on the production board --
`unable to compare active segments!` / `segment not found in
active-vec-set` -- whenever a pour is carved against 500+ overlapping
halos (measured: every zone-eligible net panicked; georust/geo#1174 is
the same crash).  Upstream replaced the sweep engine with i_overlay
(georust/geo#1234, released in 0.29).  `temper-geometry` is the only
crate that needs the fix; `temper-drc-rs` stays on 0.28.  As a
belt-and-braces the generator also snaps every input ring to a 0.001mm
grid (10x KiCad's own 4-decimal coordinate resolution) and dedupes
repeated points before the boolean.

### 1.6 Exact carve geometry (DRC-measured corrections)

The first refill run showed the carve was ALMOST at the required
separation and KiCad measured the residual.  Four corrections, each
attributed to a specific finding (commit `9c06de20`, full body):

1. **Inscribed-polygon undercut**: a 24-gon halo has edge midpoints at
   R*cos(pi/24) = 0.9914R, so a 12.6mm halo measured 12.49mm.  Radii
   inflated by 1/cos(pi/24) so the polygon's EDGES sit at the true
   distance.
2. **Rect-pad corner reach**: a pad's furthest point is a corner
   (hypot(w/2,h/2)), not max(w,h)/2 -- same half-diagonal convention
   `_ground_plane.py` already documents.
3. **Through-via span**: KiCad models a via's copper barrel on every
   layer it passes, not just its 2 named endpoints; `_via_is_on_layer`
   tests the span.
4. **Layer-honest own pads**: an F.Cu-only SMD net must not pour on
   In3.Cu (19 measured isolated-copper findings); the layer filter now
   skips layers with no own pad.

### 2.2 Production seam + kicad-cli refill

The full `route_pcb` production run was OOM-killed at 53 GB RSS on
2026-08-16 (global OOM while another agent ran a full router_v6 pytest
suite; kernel log `oom-kill pid 935359`).  Per the repo's
no-compete-on-memory rule, verification went through the exact
production emission seam instead: `_emit_zone_pours` fed the real
parsed board, the emitted 64 zone blocks spliced into a COPY of
`pcb/temper.kicad_pcb` (R7 strip + replace, same as the route path),
then `kicad-cli pcb drc --refill-zones` (10.0.5) on the copy --
`docs/evidence/2026-08-16-zone-pour-refill-verify.py`.

Measured (kicad-cli 10.0.5, --refill-zones, --severity-all):

| board state | isolated_copper | zone-involved creepage | total violations |
|---|---|---|---|
| committed board, its own 96 zones | **107** | **213** | 1977 |
| no zones at all (bare) | 0 | 0 | 1678 |
| **Rust-generated zones (this wiring)** | **0** | **0** | **1679** |

The Rust zones add **one** violation over a bare no-zone board; the
committed zones added 299.  The remaining 330 creepage findings are the
board's own pre-existing pad/track pairs (329 in the bare baseline --
the board is mostly unrouted).

The carve's exactness came from four DRC-measured corrections, each
attributed to a specific finding (commit `9c06de20`, see its body):
inscribed-polygon undercut (12.49 vs 12.60mm actual -- halo radii
inflated by 1/cos(pi/24)); rect-pad corner reach (half-diagonal, not
max(w,h)/2); through-via layer span (KiCad models the via barrel on
every layer it passes, not just its 2 named endpoints); and
layer-honest own pads (an F.Cu-only SMD net must not pour on In3.Cu --
19 measured isolated-copper findings).

Seam-level claims (docs/evidence/2026-08-16-zone-pour-seam-verify.py):
64 zones across 43 net/layer pairs; gnd In1.Cu plane present (separate
`_ground_plane.py` path, #1245); ntc-no F.Cu = 0 zones (honest 0/4 PD3
failure, was 47+ islands) while its THT pads get the design-doc-B2
sparse-inner-layer zones; creepage table HV-vs-LV = 12.6mm live.
