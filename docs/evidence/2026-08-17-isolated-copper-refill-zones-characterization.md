## 1. Working hypothesis (to be confirmed with measurement)

Re-reading #1257's own commit body (`c261907bc`) closely: its "isolated_copper
107->0" measurement was NOT taken by running `--refill-zones` against the
committed `pcb/temper.kicad_pcb`. It was taken by:

1. Calling the production emission seam (`_emit_zone_pours`, the function
   `route_pcb()` calls during a full route) directly against the real
   parsed board, using `docs/evidence/2026-08-16-zone-pour-refill-verify.py`
   (committed, read-only, still in the tree).
2. Splicing the FRESHLY Rust-generated zone outlines into a *scratch copy*
   of the board, replacing (not merging with) the committed 96 zones.
3. Running `kicad-cli pcb drc --refill-zones` on that scratch copy.

That is: `--refill-zones` WAS used by #1257, but on a board whose zone
ROSTER had already been regenerated by the fix. The committed
`pcb/temper.kicad_pcb` itself was never updated with these zones, because
the only pipeline that would do so (`route_pcb`, full route -> emission)
has been OOM-killed on every attempt (documented in #1257's own PR body,
"Outstanding" section, and independently in the handoff).

Structural check (no venv needed): every one of the committed board's 96
`(zone ...)` blocks has exactly one `(polygon ...)` element (0 with holes),
confirmed by direct regex parse of `pcb/temper.kicad_pcb`. This matches
#1257's own description of the PRE-fix state ("all 96 committed zones have
exactly one polygon, none with a hole") -- i.e. the committed zones are
still the OLD, pre-Rust-generator outlines. `grep -c filled_polygon
pcb/temper.kicad_pcb` = 0 (zones are outline-only on disk, consistent with
PR #1298's finding).

So the leading hypothesis is: **the fix works and was never disproven; it
was simply never applied to the checked-in board.** #1298's 109-113 count
reproduces (within noise, given #1279's intervening placement pass moved
components under the same static, stale zone outlines) #1257's own
BEFORE number (107) on the committed board's real zones -- not a
regression of the fix.

This is being confirmed by re-running #1257's own read-only seam+refill
harness (`docs/evidence/2026-08-16-zone-pour-refill-verify.py`) against
TODAY's committed board (post-#1279 placement pass, which #1257 predates)
to check whether the Rust-generated zone roster still measures 0
`isolated_copper` on the current board geometry, and by characterizing
the net/layer/zone breakdown of the 109-113 findings on the board's own
stale zones.
