## Bring-up gate B-E1, CM_TOL, 80-85 kHz: does the datasheet settle or sharpen them?

**B-E1 (DAC images at the modulator rate): sharpened, not settled.** The docs say the modulator rate "is unpublished" and evaluate 8/16/32/64 fs. SLAAEP0 (March 2026) Table 4-3 publishes it: the 192 kHz bin (10) runs at **OSR 16 with MOD_CLK = 3.072 MHz, or OSR 8 with MOD_CLK = 1.536 MHz**; the app note says "A higher internal MOD_CLK is generally preferred", DEM_CLK = 4 x MOD_CLK (12 MHz). At 187.5 kHz that is 16 fs = 3.000 MHz (or 8 fs = 1.5 MHz). So the 32 fs and 64 fs rows of power-spurs README-rev-e section 4 cannot occur; the live rows are 16 fs (0.73-0.78 % on a coil with no rejection credit; B-E1's own 0.06 % bound after the pass) and 8 fs (the worst, 0.14 % bound). Which of the two auto mode picks is not stated, so gate step 6 (scope FFT of SOURCE_BUF, 1-13 MHz) should look for a line at 3.0 MHz (and 6.0 MHz) vs 1.5 MHz. The datasheet's own rejection language (p69 "inherent antialias filtering with a high rejection of out-of-band frequency noise around multiple modulator frequency components") remains unquantified, and SBAA377's +/-20 kHz notch width still does not cover the 27-60 kHz tones. Pass criterion and fallback (C34/C35 -> 1 nF) unchanged.

**CM_TOL: not settled; sharpened by C-01.** Nothing in the datasheet forbids CM_TOL 01 with ADC_CHx_BW_MODE = 1: the only stated wideband conditions are 40 k input impedance and not high-swing (p48, p134, Table 8-70). Nothing characterizes it either: every ADC spec uses CM_TOL 00 (AC) or 10 (DC), the wideband SNR row (91 dB to 85 kHz, p9) is AC-coupled. New information: the fallback CM_TOL 10 is the characterized high-tolerance mode and costs about 2 dB SNR (102 vs 104), 1 dB DR, no THD+N change, so it is a cheap fallback and worth a three-way comparison at the gate. 0.85 Vpp vs 1 Vpp has 15 % margin.

**CM_TOL addendum, 2026-10-30: mostly settled by SBAA634A** (TI, "Input Common-Mode Tolerance Modes for TAx5x1x", Apr 2026, rev. Sep 2026). Table 2-3 measures the TAC5112 in all three modes on the TAC5112EVM-K (1 kHz, 100 mVpp, DC common-mode bias, averaged over both channels). At the 40 k input impedance the firmware uses: mode 0 CMRR 47 dB / SNR 102 dB / THD+N -97 dB; **mode 1 (our setting) 47 / 101 / -97**; mode 2 47 / 100 / -96. So mode 1 costs about 1 dB SNR and nothing in THD+N, and mode 2 as a fallback costs one more dB. Two corrections follow. (1) The CMRR at 40 k is 47 dB, not the 60 dB (5 k / mode 0 figure: 61 dB) used in C-13, so the common-mode-to-differential term there is about 4.5x larger (about 0.2 % of the CM component instead of 0.05 %). It is still a per-channel linear term that per-frequency calibration removes; its temperature drift remains unpublished. (2) The bring-up CM_TOL gate no longer has to discover whether mode 1 works: it only has to confirm the 1 kHz EVM numbers hold at 27-60 kHz in wideband mode, which SBAA634A does not cover.

**80-85 kHz: partly settled.** The "neither attenuation is published" statement is too pessimistic. Low-latency filters at 192 kHz class: ADC (Table 7-38, p63) ripple +/-0.06 dB to 0.456 fs = 85.5 kHz, stop-band >= 90.5 dB from 0.571 fs = 107.1 kHz; DAC (Table 7-64, p82) ripple -0.005...0 dB to 0.452 fs = 84.75 kHz, stop-band >= 86.9 dB from 0.6 fs = 112.5 kHz. The DAC image of a tone f lands at fs - f; it is >= 90.5 dB down in the ADC for **f <= 0.429 fs = 80.4 kHz** (exactly the host's warning threshold, so that is right) and the DAC adds >= 86.9 dB for f <= 75 kHz. Only 80.4 < f <= 85 kHz lies in a transition band for ADC (and DAC above 75 kHz), where the datasheet gives plots only (Fig 7-56: roughly -40 to -70 dB around 0.55 fs, read off a graph to about +/-15 dB). So the 80/85 kHz measurement stays, but it only matters above 80.4 kHz. Also: 85 kHz is 0.25 kHz beyond the DAC's specified passband (84.75 kHz), and group delay / phase deviation for the low-latency ADC are specified only to 0.327 fs = 61.3 kHz (Table 7-38) so anything above 61 kHz rests on the plot (common to both channels, cancels in the ratio). The analog input bandwidth in wideband mode ("90kHz" p10) is quoted for fs > 192 kHz; at fs <= 192 kHz the quoted limit is 0.46 fs = 86.3 kHz. No -3 dB analog bandwidth is tabulated.
