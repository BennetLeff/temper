# G0: bounded campaign adapter (corrected scope)

Created: 2026-09-17. Status: **implemented and accepted for source-only and
bounded single-boost numerical work**; it does not qualify candidates and does
not close any assembly or hardware gap.

## What G0 actually is

The original plan asked for a new harness with schemas, content identity,
replay parity and a 23-mutation checker, budgeted at four hours for one owner.
Review found that the matched-power solve it specified already existed in
`pfc_candidates::LineModel`, so this revision **parameterizes that solver
instead of forking a second one** and adds only the campaign binding.

Delta, all in `zapote/packages/zapote-harness`:

| Item | Change |
| --- | --- |
| `src/pfc_candidates.rs` | `LineModel` gains `inductance_h`; `new` delegates to a new `with_inductance`; `LineModel` and its solve methods become `pub(crate)`. Nominal behaviour is unchanged. |
| `src/pfc_campaign.rs` | New. Typed manifest, matched-power solve, derating, `UNSUPPORTED` at a model-domain boundary, census. |
| `src/bin/zapote-pfc-campaign.rs` | New CLI. |
| `tests/pfc_campaign.rs` | New acceptance tests. |

No physics was added. `total_switch_gate_w` is a named subtotal
(mosfet conduction + switching overlap + output capacitance + gate charge), not
a whole-assembly total.

## Manifest schema (`zapote.pfc.campaign-manifest.v1`)

`device` and `drive` are shared by every case; `cases` carry the swept
variables. Unknown keys, an unknown schema, a missing field, a non-finite or
non-positive physical quantity, and duplicate `case_id`s are all rejected
before any physics runs.

```json
{
  "schema": "zapote.pfc.campaign-manifest.v1",
  "device": {"id":"IPW65R045C7","qg_c":9.3e-8,"qgd_c":3.0e-8,"plateau_v":5.4,
             "intrinsic_gate_r_ohm":0.85,"eoss_j":1.17e-5,"rds_on_ohm":0.045},
  "drive":  {"gate_bias_v":12.0,"external_gate_r_on_ohm":9.7,
             "external_gate_r_off_ohm":5.3,"driver_source_peak_a":5.0,
             "driver_sink_peak_a":5.0,"current_transfer_charge_c":1.0e-8,
             "loop_inductance_h":1.0e-8,"timestep_s":2.5e-10},
  "cases": [
    {"case_id":"r0-120","line_rms_v":120.0,"bus_v":400.0,"inductance_h":1.8e-4,
     "switching_hz":129107.39198576905,"requested_power_w":1796.31003212911,
     "input_rms_ceiling_a":15.0}
  ]
}
```

Case status: `SOLVED` (requested power met inside the ceiling), `DERATED`
(requirement exceeded the ceiling; achieved power and shortfall recorded),
`UNSUPPORTED` (model-domain gap; no number is fabricated). A `DERATED` case is
never ranked against a `SOLVED` one at unequal processed power.

## Acceptance evidence

`tests/pfc_campaign.rs`, all passing: baseline parity; the ceiling is not
reported as derated; low-line derating; a DCM domain boundary returns
`UNSUPPORTED` rather than a zero-loss case; fixed-`L*f` invariance with a
monotone total (the measured degeneracy as a regression); explicit inductance
reaching the waveform; one result per declared case; duplicate-id, unknown-
schema, unknown-field and non-finite rejection. The retained
`pfc_candidates` unit tests (11) still pass unchanged.

## Known limits — do not treat G0 as more than it is

* **The frequency axis is degenerate.** At fixed `L*f` every current moment is
  invariant and only f-proportional terms move, so the plan's six frequency
  cases are a monotone walk. See `tests/frequency_lf_axis_probe.rs`. A
  frequency case needs a sourced magnetic (core/winding loss and volume) to
  carry information.
* **The model is not validated against any external per-device measurement.**
  The B-TI and B-INF references both returned `INSUFFICIENT_EVIDENCE` for the
  switching-energy claim; both named the same missing observation (a
  device-level clamped-inductive capture). The only external check obtained is
  a whole-board loss bound (`tests/reference_loss_bound_probe.rs`), which is
  necessary but not sufficient.
* **No assembly completeness.** The ledger's other terms (bridge, inductor,
  shunt, capacitors, EMI, auxiliaries) are out of scope here; `total_loss_w`
  and whole-assembly mass/volume/cost remain absent.
* **No thermal ranking.** There is still no frozen ambient/cooling contract.
