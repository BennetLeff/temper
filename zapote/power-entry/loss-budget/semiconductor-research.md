## Explicit gaps blocking a bounded total loss

1. The existing Rust ideal CCM model supplies branch RMS, mean and edge currents; those are model predictions, not measured controller behavior. Hot winding/core loss and actual PF/zero-crossing distortion remain unverified.
2. MOSFET switching energy (Eon/Eoff) at ~390 V, actual current, temperature, gate resistance, layout overshoot, and UCC28180 drive waveform is absent; td/tr/tf are resistive-load timing tests and cannot substitute.
3. C3D20065D capacitive-loss path depends on commutation and voltage waveform; QC/Ec are typical single-condition values, not a guaranteed per-cycle loss.
4. Bridge VF is specified at one current and temperature; line-angle current distribution and heatsink interface are unspecified. The 25 A IF(AV) rating assumes a large test plate.
5. No heatsink model/interface/contact resistance or insulated shared-sink arrangement is specified for TO-247 parts; RthetaJC alone cannot establish junction temperature.
6. UCC28180 SOIC thermal metrics are board simulations; PCB copper, airflow, and neighboring heat sources are unqualified.
7. **Resolved.** The authored and native order code is `STW65N65DM2AG`; the physical package marking is `65N65DM2`. No indexed vendor or distributor page carries a bare non-AG `STW65N65DM2` as an orderable part. `STW63N65DM2` is a different, separately orderable device. The authored source, BOM and native board now agree on the AG order code; routing was preserved during native regeneration.

Coordinator review: the Wolfspeed p2 footnotes print 1.3 K/W with the per-device marker and 0.65 K/W with the per-leg marker, which conflicts with the intuitive parallel-die interpretation and p1 dissipation ratings. Do not silently reverse them or use either for a package acceptance model without adjudication. The budget currently uses neither. The semiconductor table is research context, not executable exact-part acceptance data.
