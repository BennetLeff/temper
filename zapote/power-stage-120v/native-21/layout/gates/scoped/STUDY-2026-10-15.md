# Scoped verification for the native-21 build chain

**Snapshot:** cb48a12e6 (board of record s43).
**Proposed patch:** `scoped-verify.patch`. It adds `native-21/layout/gates/scoped/` and edits `chain.sh`, `regate.sh`,
`scorecard.py` and `gates/README.md`. Nothing is committed. The full chain was not run.

## Summary

- **Where the time goes.** A chain is 29.4 minutes of wall time and about 92 worker-minutes.
  - The thermal block takes 22.2 minutes of the critical path (76 %): task 04 (6.7 min, 6 workers), the B3 legacy study
    and sweep (6.1 min), and the B3 ratings (9.4 min, 4 workers).
  - Build plus DRC refill takes 3.5 minutes, the Rust barrier 2.6 minutes and D5 0.9 minutes.
  - Everything else is seconds.
  - The B3 ratings is not cached today. It reruns on every chain, even when copper, model and heat are unchanged.
- **Design.** The scoped mode classifies every changed path against a dependency map and rebuilds the board only when a
  board input changed.
  - On every rebuilt board, all safety gates and cheap steps rerun.
  - The four thermal steps are reused only when their content key matches the benchmark manifest's.
  - Unknown paths, stack-up changes and changes to the chain itself force the full chain.
  - The scoped card names every entry as recomputed, reused (with the key that proves it) or stale.
- **Back-test.** 17 historical cases: 7 stage pairs (s28→s29, s30→s31, s35→s38, s38→s40, s40→s41, s41→s42, s42→s43)
  and 10 card re-scores.
  - The policy plan reused 106 card entries and produced **0 misses**.
  - A stricter variant, which reruns only steps whose own reads changed, reused 252 entries and had 1 miss. The miss
    traces to card provenance (see below). It is why cheap steps always rerun in the proposed design.
- **Gain.**

  | Lane | Today | Scoped | Worker-min (today → scoped) |
  |---|---|---|---|
  | Parts-only (MPN / value, same footprint and copper) | 16.8 min with today's caches, 29.4 cold | 7.3 min | 46.6 → 7.9 |
  | B3 ratings model or firmware fan law | 16.8 min | 9.7 min | |
  | B3 solver | 29.4 min | 15.7 min | |
  | Task-04 model | 29.4 min | 22.5 min | |
  | Desk, card, gate-script change | 16.8 min | 0.4 min | |
  | One-island layout lane | 29.4 min | 29.4 min | no gain |

  The layout lane gains nothing because any copper change reruns B3, which reads all copper.
  The lever for layout lanes is outside scoping. Running the B3 legacy study and sweep beside the ratings solves,
  instead of before them, takes every thermal run from 29.4 to 23.3 minutes (a recommendation; not in the patch).

## 2. Dependency map

`gates/scoped/depmap.json` is the machine-readable map. For each step it gives the wall time, the workers and the
policy; the card entries and outputs; the read set; the content files that keys hash (`step_files`); and the path
rules.

| Input class | How it is detected | Reruns | Reused when |
|---|---|---|---|
| bom_only: MPN / value, same footprint | frozen BOM paths (class build), then post-build: equal canonical copper key and `part_geom`, changed `part` value | build, DRC, D5, barrier, fab, every cheap gate | task 04, B3, sweep, ratings: when their keys hold. The heat files are regenerated before keying, so a loss change is caught. |
| Placement / footprint | `part_geom` per ref | rebuild; copper key changes (pads are in it), so all thermal reruns | — |
| Copper on net set N | copper.json / patches; post-build `net_own` and `net_fill` (13 mm refill reach) per net | rebuild; all thermal (B3 reads every net); manual necks / pickup become STALE if their nets' `net_fill` changed | manual studies whose nets are untouched |
| Thermal model scripts | path → step (`step_files`) | task 04 → B3 → ratings, each only if its own files changed. A task-04 rerun propagates downstream. | build, every gate, and the thermal steps upstream of the change |
| Stack-up | `native-21/stackup*.json` | **full chain** | — |
| Firmware | `firmware/components/control/thermal_mgmt.h` → ratings; other firmware is read by no step | ratings | everything else |
| Gate script / desk / ledger / sourcing | path → step | that step (cheap) or the card | all expensive steps |
| Docs, records, studies | `**/*.md`, 10/11/12/13 folders, dated studies | nothing expensive. The card always reruns, and it must: see finding 3. | |
| Unknown path, chain.sh, regate.sh, gates/scoped | default | **full chain** | — |

**Reconciliation with `13-coupling/results/verification.json`** (`depmap_check.py`, all six controls pass):

- **C1.** Every s43 card entry has a producer step, and every claimed entry is on the card.
- **C2.** All 34 verification metrics map to a step.
- **Ten card entries postdate verification.json (s32).** The audit does not know them; the map does:
  - b3_ratings and its three margins;
  - jet_strip_height;
  - bank_ratio_tdk_28A_35k;
  - four track-geometry entries.
- **The 11 global metrics** are all "rebuild" or "cheap" steps in the map, so they run on every rebuilt board:
  DRC ×3, DFM, vias, fit, audit.rs, ledger ×2, cost, CPL audit.
- **The map is deliberately wider than verification.json in three places:**
  - **B3.** The audit models B3 as 9 nets plus 41 heat parts, a heat share that is right for attributing groups. The
    B3 geometry, however, is the copper of the whole board, so the cache key is the whole board's copper.
  - **Task 04.** The audit lists 12 nets. The export covers 14 nets plus refill reach.
  - **Barrier and D5.** The audit lists 77 nets. The map runs them on every rebuild, as a safety policy.
- **C3.** The explicit read sets contain verification.json's.
- **C4.** 83 path literals in the thermal scripts, `chain.sh`, `regate.sh`, `incr_iter.sh` and `scorecard.py` each
  reach their step. Two citations are allowlisted with reasons.
- **C5.** The only firmware file read is `thermal_mgmt.h`.
- **C6.** The recursive import closure of task 04, B3 and the ratings reaches the right step.

## 3. Design

The design is in `gates/scoped/README.md`; it is summarised here.

- **Benchmark.** Every full `chain.sh` run writes `BUILDDIR/scoped-manifest.json`. It records:
  - the board SHA and both copper keys (raw and canonical);
  - the per-net and per-part keys;
  - the keys of the keyed and manual steps, and their step files;
  - the npz hash, the margins board and the git HEAD with any dirty paths.
- **Scoped run.** `scoped_chain.py run TAG PASSDIR BUILDDIR --bench-build FULL_BUILD` works in four stages:
  1. **Classify** the paths changed from the benchmark commit to the working tree.
  2. **FULL** if a path is unknown or touches the chain or the stack-up. Then `chain.sh` runs unscoped.
  3. **REBUILD** if a board input changed. Otherwise **REUSE-BUILD**: the benchmark build is copied, and its
     board SHA is checked.
  4. Write `scoped-plan.json` and run `chain.sh` with `SCOPED_PLAN`. `chain.sh` asks `want STEP` before:
     - the build;
     - D5;
     - the Rust barrier (`REGATE_SKIP_BARRIER`);
     - task 04, B3 and the ratings.
- **After copper_key**, `chain.sh` calls `scoped_chain.py decide`. It does three things:
  - regenerates the heat sources;
  - computes the candidate's keys;
  - finalises the keyed and manual decisions against the manifest, and checks the local artefacts a reuse needs.
- **Safety rules.**
  - An unknown path forces the full chain.
  - A path rule that names a step makes it run, whatever its key says.
  - A task-04 rerun propagates downstream.
  - On a rebuilt board, B3 forces task 04 (`thermal.py`'s same-board check).
  - A reused value the card can recompute is recomputed from the reused outputs. A carried value becomes STALE if
    the scorecard itself changed.
  - `scorecard.py --compare` refuses a scoped card as a benchmark, and rejects a scoped card that still has stale
    entries. Every scoped verdict prints "full chain still due at merge".
- **Merge.** The full chain stays mandatory before merging to `codex/power-stage-integration`. A scoped card is
  provisional evidence for the lane's iteration, not the card of record.

## 5. Back-test (`gates/scoped/backtest.py`; `backtest/results.json`, `backtest/results.txt`)

**Method.** Each case compares a candidate tree and card with the benchmark tree and card.
- **Stage pairs:** the parent of the stage commit against the records commit.
- **Re-score pairs:** one card before and after a later commit rewrote it.
- **Board keys:** from each card's own build directory. `net_keys.py` runs on `BUILD/section.kicad_pcb`, whose SHA
  matches the card's `board_sha256` for all 10 builds.
- **Miss rule:** a MISS is an entry of a reused step that differs between the two cards.

**Two plans are checked.**
- **Policy plan (proposed):** cheap steps always rerun; expensive steps are reused by key.
- **Strict plan:** reruns only steps whose own reads changed, using the coupling audit's read sets with 13 mm refill
  reach. It is a stress test of the read model.

**Results.**

- **Policy plan: 0 misses** over 106 reused entries.
  - In every re-score, the entries that moved belonged to steps the plan recomputed. Examples: the ratings margins at
    59281e65a and 352efaf14; the buildability entries at de794f21d; the ledger at 3367e789b.
  - In the layout stages, everything that moved was recomputed: the B3 peaks and margins, cost, vias and track
    geometry. Every non-thermal gate and metric was unchanged, but it reran in seconds.
- **Strict plan: 1 miss.** `gates.jet_strip_height` at the s43 re-score is absent from the cb7d7a76e card and present
  at dc074c47c.
  - The jet-strip gate (710572d54, 13:35:51) is an ancestor of the s43 records commit. The s43 chain, however, ran
    from 13:15 to 13:44 with the earlier `chain.sh`. No `native21-jet-strip.json` was written in that window. The
    card at cb7d7a76e is therefore older than its own tree.
  - A strict scoped run would have reused `fit` and kept the old answer.
  - The policy plan reruns `fit` (cheap) and is immune. With manifests, which record the HEAD the benchmark was
    actually built from, the jet-strip script shows as a changed path.
  - I count this as a failure of the strict variant. It is the reason cheap steps always rerun.
- **Two more provenance effects.** The policy plan absorbed both because the card always reruns:
  - s35 65c6bd08e: the track-geometry entries appear with no input change, because the candidate card predates the
    scorecard metric.
  - s38 f8cca7d21: `ledger_violations` goes 0 → 1 with only `.md` files changed (see finding 3).

**What the back-test does not cover.**
- **Ratings reuse on a rebuilt board.** No parts-only stage happened after the ratings gate arrived (s35). History
  exercises ratings reuse only on the same board (four re-scores, entries equal). On a rebuilt board it rests on two
  things: the key, which covers every input found by C4 and C6, and the copper-key standard that the existing task-04
  and B3 caches already use. In s26, s29 and s31 the existing task-04 and B3 caches hit on unchanged copper.
- **Per-net thermal reuse.** It was never tried. B3 reads all copper.
- **End-to-end runs.** The chain patch has not been run end to end. It passes `sh -n`, the `want` guard was exercised
  in a harness (scoped and full semantics, subshell inheritance), and the patch applies cleanly to the snapshot gates
  (unchanged on the integration HEAD).

## 7. Findings along the way

1. **B3 ratings has no cache.** It costs 9.4 min × 4 workers on every chain. `margins.json` must carry this build's
   board SHA, so even a parts-only chain, with task 04 and B3 cache hits, reruns it. This is the largest single
   saving in the parts lane.
2. **`copper_key.py` hashes the `.kicad_pro` raw.**
   - The s30 and s31 build directories carry identical copper. Their raw copper keys differ only because s31's
     `.kicad_pro` gained `erc` and `schematic` sections at 22:53, seven hours after its chain. At chain time, s31 logged
     a task-04 cache hit.
   - Anything that touches a build directory's `.kicad_pro` (a GUI open, a later ERC) turns the next cache lookup into
     a 22-minute recompute.
   - `net_keys.py` adds `copper_key_canonical`, which drops those sections. The scoped keys use it.
   - Recommended: the same change in `copper_key.py`. It is not in the patch, because it changes the existing cache key
     once.
3. **The datasheet-ledger gate reads documents.**
   - It verifies citations by line count in cited files, `.md` included.
   - The s38 adopt commit f8cca7d21 changed only `DECISIONS.md`, `OPEN-ITEMS.md` and READMEs, yet the card's
     `ledger_violations` went 0 → 1.
   - Treating docs as non-inputs is therefore safe only because the card (and with it the ledger) always reruns.
     `depmap.json` records this.
4. **`model_key` hashes the whole `stackup.json`.** The post-s43 commit f125aad4a changed only the status text and the
   laminate names (Nan Ya → Kingboard). All numbers are unchanged. The next chain will still miss both thermal caches,
   about 22 minutes. The scoped map stays conservative here: a stack-up change runs the full chain. A canonical
   numeric projection of the stack-up for the thermal keys would fix it.
5. **The ratings model's physical inputs are frozen files, not the BOM or placement.** `part-bodies.json` is a stage-19b
   extraction, and the limits are hard-coded per reference. A scoped reuse reproduces the full chain's answer exactly,
   but neither notices an MPN swap on a gated part. The ledger (BOM-tied, always rerun) is the check that does.
6. **The B3 legacy study and sweep (6.1 min) feed only reference-only card entries.** They run serially before the
   ratings, which do not read their outputs. Run in parallel with the ratings, they take every thermal run from
   29.4 to 23.3 minutes at +1 core (recommendation, not in the patch).

## 8. The patch

`scoped-verify.patch` (1.2 MB, mostly the committed board keys for the back-test). The paths are relative to the
repository root.

    cd <fresh worktree on codex/power-stage-integration>
    git apply --check /Users/bennet/.claude/jobs/fbfc46b4/tmp/scoped-verify/scoped-verify.patch
    git apply /Users/bennet/.claude/jobs/fbfc46b4/tmp/scoped-verify/scoped-verify.patch
    G=zapote/power-stage-120v/native-21/layout/gates
    python3 -I $G/scoped/test_scoped.py          # 16 controls
    python3 -I $G/scoped/depmap_check.py         # C1-C6
    python3 -I $G/scoped/backtest.py             # 17 cases, 0 policy misses (keys cached in scoped/backtest-netkeys)
    python3 -I $G/scoped/estimate.py

**What the patch changes.**
- **`chain.sh`:**
  - `want STEP` guards on the build, D5, task 04, B3 and the ratings, plus the barrier skip through `regate.sh`;
  - the `decide` hook after copper_key;
  - the manifest written at the end, non-fatal.
  - With `SCOPED_PLAN` unset, every guard is true. The only new behaviour is the 2-second manifest at the end.
- **`regate.sh`:** `REGATE_SKIP_BARRIER` reuses a present `barrier-gate-rust.json`. Only scoped runs set it.
- **`scorecard.py`:** refuses a scoped card as a benchmark, and rejects a scoped card that has stale entries.
- **`gates/README.md`:** a usage paragraph.

**Activation.** The first full chain after applying the patch writes the first manifest. That build becomes the
benchmark for scoped runs.

**Not done.**
- The patch was not exercised with a real chain run.
- The first scoped run should be a dry run (`--dry-run`), followed by one parts-only lane checked against a full
  chain on the same commit.
