# D6 method and limits

Source snapshot: `1f09223516cc37d00f73b5e5e6d33a0197d7a30d`. Board inputs were not edited or re-extracted. This is a circuit-design proposal study, not geometry or physical qualification. Only this output directory is changed.

The brief's two baseline requirements differ. It explicitly requests `d2/legA-h0-lin12-m20corr.matrix.txt`, but grid v2 used `d2/legA-h0-lin12.matrix.txt`. Therefore first reproduce the selected grid-v2 cases with the **original** matrix, then establish a **corrected** baseline and use that identical matrix for every remedy. `summary.json` records the original replay and each correction delta. No comparison attributes the matrix correction to a gate remedy.

`run_study.py` delegates matrix conversion and execution to unchanged `d2/run_d2.py` and the sim-kit runner. The electrical baseline is unchanged: added `.meas` instrumentation does not insert circuit elements. Each proposed variant has a committed complete deck in `decks/`. Matrix values, coupling conversion, driver resistance, MOSFET library, default temperature, snubbers, shunt, bulk branch, solver tolerances and edge commands are held fixed. Both directions run for S1=(170/198/280V,37A, 307/348 ns), S2=(280V,71A, 348 ns), S4=(198V,−20A, 348 ns), capacitor ESL 10 nH. DIR0 turns the low side off first; DIR1 the high side. Max timestep is 0.2 ns. “DT” is command separation here, not guaranteed gate dead time.

The upstream runner copies the licensed library into each temporary run. The D6 wrapper removes only those copies from its own result directories after execution; no vendor model is committed. Each case retains exact parameters, the full simulator log and machine-readable measurements. Simulation uses the library's L1 model with default TEMP 27°C. Datasheet/vendor-source and script hashes are preserved in provenance and execution-identity records. `run_study_initial.py.txt` is the exact original runner source used before the first solver abort. The later version preserves invalid rows and supports identity-checked resumption; existing successful data was neither overwritten nor relabeled. Rows without `execution_identity` use the original group `identity.json`; later rows name their identity file. Failed rows never establish a pass.

Overlap-energy instrumentation computes die-port drain current through the vendor L1 drain resistor as `(V(ldrd)−V(dd))/74.4µΩ`, positive into the die drain. Integrate `VDS×ID` separately for both MOSFETs. The first window is T1 through T1+DT (outgoing command/dead interval); the second T1+DT through T1+DT+750ns (incoming command and settling). The tables sum both devices' **positive** integrals per window; raw results also retain signed integrals per device. This prevents cancellation from disguising overlap, but it is deliberately not a total switching-loss prediction: Coss energy exchange, reverse conduction, recovery and ringing all contribute, and delayed outgoing behavior can cross into the second window. These values exclude gate-driver/supply losses and must not be multiplied by switching frequency as a qualified thermal budget.

`probe_waveforms.py` retains only the transition window as compressed CSV and checks independent trapezoidal integration against ngspice `.meas`. Signed-energy error is scaled by the integral of absolute power to avoid a near-cancellation denominator; positive-energy error uses its positive integral. The audit tolerance is 0.1% of that scale, with a 1 nJ absolute floor. The initial signed-relative audit stopped on an 0.088 µJ difference in the S4 baseline; preserved raw data showed only 0.060% positive-energy disagreement. Both values remain visible. `probe_waveforms_initial.py.txt` preserves the earlier audit source; the subsequent version resumes analysis from the saved raw run without retrying the circuit. A 0.1ns timestep check bounds numerical sensitivity of the selected representative S1/S4 cases, not the entire sweep's physical uncertainty. No convergence setting is relaxed to turn an aborted point into a pass.

The four-port corrected matrix remains provisional, with the extrapolation, crop correction and bulk coupling limitations documented upstream. The original driver approximation lacks the transient pull-up behavior discussed in D2; this study holds that approximation fixed to isolate remedies. The unresolved high-slew diode-recovery realism from D3 can change S4. No lot/process, hot-junction, driver tolerance, capacitor tolerance, diode selection, added component inductance, supply transient/startup or PCB layout qualification is supplied. Added components and changed bias rails are proposals only. D5's firmware/path analysis determines which command separations hardware can actually reach; a firmware comment cannot remove cases from this study.
