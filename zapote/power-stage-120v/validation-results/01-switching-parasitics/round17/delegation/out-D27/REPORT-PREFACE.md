## Contradictions and proposed resolutions

### C1 — inter-leg modulation policy (R23)

**Decision evidence:** [DECISIONS.md:68](https://github.com/BennetLeff/temper/blob/212c497f9e762f87ed59ba38842dfaeedc7aa538/zapote/power-stage-120v/DECISIONS.md#L68) says complementary pairs, legs 180° apart at 50% duty. It also permits synchronized frequency/phase updates, so the text needs to distinguish a default operating point from an allowed modulation range. [D20 R21–R23:67–69](https://github.com/BennetLeff/temper/blob/212c497f9e762f87ed59ba38842dfaeedc7aa538/zapote/power-stage-120v/validation-results/01-switching-parasitics/round17/delegation/out-D20/CONTROLLER-REQUIREMENTS.md#L67-L69) requires approved frequency/duty/phase limits and capacitive-operation inhibition; it is not a qualified pan map.

**Prototype evidence:** [round4 firmware:56–73](https://github.com/BennetLeff/temper/blob/212c497f9e762f87ed59ba38842dfaeedc7aa538/zapote/power-stage-120v/prototype-closure/round4/firmware/README.md#L56-L73) deliberately selects fixed-frequency variable phase, with A/B separation from zero to half a period, and blocks the legacy PLL/burst paths. [Target:48–54](https://github.com/BennetLeff/temper/blob/212c497f9e762f87ed59ba38842dfaeedc7aa538/zapote/power-stage-120v/prototype-closure/round5/firmware/esp32/mcpwm_target.c#L48-L54) rejects the half-period endpoint. Thus the current literal decision, intended controller and inhibited target do not describe one enabled operating policy. No live gate behavior is alleged.

**Consequence and proposal:** the control owner should decide whether 180° is a fixed policy or a named endpoint/default within an approved phase range. If fixed, bring the prototype policy into conformance; if variable phase is intended, explicitly amend the decision and qualify that operating envelope, endpoint and CT phase inhibit. In either case retain the selected 200 ns controller gap, common timer, independent PERMIT, and atomic timer-zero update requirement. Recheck switching/ZVS, loss and inlet-current evidence over the chosen envelope; the existing S1/S2 cases do not establish that envelope. Do not silently treat the later prototype implementation as an owner decision. Evidence for the gap and case limits: rows R21/R24/R25/R73.

### C2 — the prototype target does not meet D25's final PWM state (R27)

**Decision evidence:** [DECISIONS.md:72](https://github.com/BennetLeff/temper/blob/212c497f9e762f87ed59ba38842dfaeedc7aa538/zapote/power-stage-120v/DECISIONS.md#L72) requires every failure/cleanup path to finish with each PWM pad push-pull low, pull-up disabled, pull-down enabled, after generator deletion. It cites the ESP-IDF reset behavior and adds external ≤10 kΩ PWM pull-downs.

**Prototype evidence:** [inhibit():21–34](https://github.com/BennetLeff/temper/blob/212c497f9e762f87ed59ba38842dfaeedc7aa538/zapote/power-stage-120v/prototype-closure/round5/firmware/esp32/mcpwm_target.c#L21-L34) calls `gpio_reset_pin`, then level/direction setters, but never disables the pull-up or enables the pull-down and ignores GPIO errors. [Initialization:82–120](https://github.com/BennetLeff/temper/blob/212c497f9e762f87ed59ba38842dfaeedc7aa538/zapote/power-stage-120v/prototype-closure/round5/firmware/esp32/mcpwm_target.c#L82-L120) has early returns before the common inhibit path. It has no generator-deletion cleanup today. This is a separate source implementation from draft D21; amending D21 alone cannot repair it.

**Consequence and proposal:** the firmware owner should use one final pad-restoration path after any resource cleanup, route every partial-init/update failure through it, propagate GPIO errors, and add fault-injection coverage with the real reset semantics. Preserve request/PERMIT low independently and add the controller pull-downs to the hardware contract. The currently inhibited image is not evidence of unintended heating, but it does not meet the chosen pad-state requirement. Keep commissioning disabled until both implementations and the actual pin waveforms are checked. No firmware was modified or executed for this source audit. Evidence for the inhibited state and missing hardware implementation: rows R21/R28/R29/R39.

## Other consequential reconciliation work

- **Native bus sensing is still missing from the prototype controller packet.** The separate supervisor channel does not satisfy the OPA2388/GPIO2 ADC1 path, 20 ksample/s acquisition, 150 µs freshness, calibrated thresholds or harness acceptance. Keep each requirement open or explicitly approve a replacement architecture with equivalent acceptance tests. Rows R31–R35/R75.
- **The custom sink fits nominally but has no qualified thermal curve.** Retain the ≤0.15 °C/W, ≥20 CFM and interface requirements; obtain assembly data before selecting it. D18's catalog dimensions are not evidence for a shortened custom sink. Rows R05–R11.
- **Refresh stale handoff prose without rewriting historical receipts.** R5's old order code/pad-2 net, old 39 kΩ timing requests, capacitor-ESL progress, extrapolation progress and leg-B status need reconciliation. Leg-B finite-height solutions do not close the native17→19 B carry-over or a full coupled campaign. Rows R12/R14/R53–R55/R72/R77/R78.
- **Keep accessory decisions explicit.** Precharge, catch, the STM32 supervisor, revised protection parts and the new central board are prototype proposals with their own implementation gaps. Neither round17's local switching pass nor the filter volume authorizes those additions. Rows R30/R47–R51/R66/R74.
