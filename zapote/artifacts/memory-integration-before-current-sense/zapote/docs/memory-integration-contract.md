# Memory integration scope

Approved by the user on 2026-09-11 following the three-layer learning/memory/
validator design. Reuse the existing Rust memory policy under Zapote ownership;
keep current KiCad editing and engineering validation behavior unchanged.

Deliver reviewed, immutable, content-bound RTD guidance in zapote/skills,
Rust validation/selection with explicit applicability and source dependencies,
and a thin construction-request transport that records exactly what is sent.
A prepared prompt or file is not delivered memory. Persist the outbound prompt
at the actual process/provider boundary and separate dispatch completion,
reported use, and actual helper execution. Failure or timeout must remain
visible; never infer a helper ran from a model's prose.

Transfer procedures across units. Keep RTD numeric bounds attached to RTD
source/evidence and out of another unit's constraints. Candidate/rejected,
tampered, missing required, incompatible or oversized memory cannot silently
become a successful selection. Current constraints and validators override
advisory memory. No automatic lesson promotion from an unreviewed response.

Root owns catalog, documentation, port ledger, integration and verification.
Luna policy worker owns new Rust memory modules/tests and CLI registration;
Luna transport worker owns new Zapote Python transport/tests. Use isolated
worktrees and retain prior evidence. No CAD edit, new placer/router, legacy
memory mutation, commit or push is part of this change.
